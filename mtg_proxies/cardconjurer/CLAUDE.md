## mtg_proxies/cardconjurer/

Headless Card Conjurer frame rendering, orchestrated from `cli.py`'s `_run_cardconjurer` (per-deck Node harness invocation via `node/harness.js`, slot-prefixed PNG outputs, `fallback.txt` + `report.csv`).

## DFC handling

- Transform/modal_dfc cards render as two separate PNGs BY DEFAULT (`<slug>.png` + `<slug>_back.png`, `out`/`out_back` in the harness response, `png_back` column in `report.csv`), using CC's real DFC frame packs: transform title icon mapped from Scryfall `frame_effects`, gray reverse-P/T reminder on transform fronts, MDFC flipside bar tinted with the other face's color and filled with its name + mana/type, legendary crowns via the engine's autoFrame builders.
- `--dfc-flip` (deck-wide flag, or `#cardconjurer --dfc-flip` per-card modeline; per-card `--dfc-split` overrides the deck flag) merges both faces into one Kamigawa-flip card instead.
- `reversible_card` always stays on the flip path; saga-faced and planeswalker-faced DFCs skip to `fallback.txt`.
- In `print`, `#cardconjurer --dfc-split` is warned-and-ignored — flip only.

## Art sources

- MTGPics (`mtgpics.py`) is tried first for single-faced cards, then Scryfall's `art_crop`. Every MTGPics image is vetted against the card's own `art_crop` first (`art_check.py`, called from `cli.py`'s `_mtgpics_rejection`): Scryfall's crop must be found inside it (luminance NCC at 128px over 10 scales: accept ≥0.90 whatever the colour grading, 0.78–0.90 only with a mean colour gap ≤0.06; measured wrong pairings peak at 0.77) and, when the optional `art-check` extra (rapidocr-onnxruntime) is installed, it must carry no overlay text (WotC / MEE / Magic / LOTR wording, web addresses, "Artist:", or the artist's / card's name spelled out; short fragments and painted signatures are ignored). A rejected image is never edited — the card uses Scryfall's art (upscaled as usual) and the run prints a `Note:` with the reason. Verdicts are cached as `<image>.check.json` (`CHECK_VERSION`); a verdict reached without OCR is redone once OCR is installed. Borderless renders (full-bleed MTGPics art only) are not vetted.

## Frame styles

- Set symbols come from CC's local official library per card set (no 8ED hardcode); `--set-symbol` overrides.
- `--8th` (2003), `--modern` (M15), `--m15-8th`, `--retro` (Seventh Edition 1997) are mutually exclusive (CLI group + modeline mutex).
- `--m15-8th`: a modern M15 card body restyled with 8th-Edition trim — shares modern's size/legend-crown/P-T-box geometry via engine-native `autoFrameUnified('M15Eighth')` and the `makeM15EighthFrameByLetter` crown builder; transform/MDFC split faces use `packM15Eighth*` DFC packs. Never auto-selected — no Scryfall `frame` value maps to it. Its bottom-info line drops the real-card copyright/legal text and shows a compact `(SET) NUMBER` print-staging tag instead, right-aligned to mirror the artist icon's left-margin gap, capped before the P/T box on creatures/vehicles — a long copyright string was found to collide with long artist names there.
- `--retro`: engine-native `autoFrameUnified('Seventh')`, per-color land frames, tombstone icon via `frame_effects`, battlement legend crown on single-faced legendaries, planeswalkers included (default on, `--no-crown` / `#cardconjurer --no-crown` opts out; job key `no_crown`). The crown is ours, not CC's: `retro_crown.py` generates one layer per Seventh frame image plus a crown `Pinline` mask into `node/assets/retro-crown/` (committed; regenerate with `uv run python -m mtg_proxies.cardconjurer.retro_crown`), and `harness.js`'s `addRetroLegendCrown` replays the card's frame stack with them (Frame mask → unmasked crown layer, Pinline → crown pinline, Right Half kept, any other mask skips the layer), so hybrid / two-colour / land stacks all carry into the crown. Pinlines are stock on retro: no `--legendary` gold pinline (removed; `--legendary` is a no-op on retro, it only adds CC's crown on 8th) and no two-tone pinline on two-colour gold cards (their colours show in the textbox only); transform/MDFC split faces use the Classicshifted retro DFC packs with native crowns, transform icon/indicator, and pre-colored flipside bars.
- `--retro-hd` (job key `retro_hd`, per card `#cardconjurer --retro-hd`): retro with frame art composited from Gavin Bowers' Proxyshop Retro template, which is drawn on packSeventh's own geometry. `retro_hd.py` (optional extra `retro-hd` = psd-tools) downloads the ~840 MB PSD into `~/.cache/mtg-proxies/retro-hd/` (not committed: not ours to redistribute) and composites one 2010x2814 image per packSeventh frame code (`VARIANTS`: w u b r g m a c l wl..gl), mirroring Proxyshop's `RetroTemplate.enable_frame_layers` for a Normal-size card (frame texture clipped to the frame shape, light/dark bevel fills through their masks, textbox clipped to its shape incl. ragged black/green, textbox bevels, land pinlines, outlines, black border), plus HD crown layers (`retro_crown.HD_GEOMETRY`). The harness keeps the whole retro path and only remaps image loads: while `renderFace` builds a retro-HD card, `resolveSrc` sends `/img/frames/seventh/regular/<code>.png` to the HD composite, and the crown replay reads `retro-hd/crown/`. Single-faced cards only, planeswalkers included (DFC faces use Classicshifted; packPlaneswalkerSeventh draws its loyalty badges over the same frame images, so they carry over). The CLI refuses `--retro-hd` with a non-retro frame and exits with build instructions when the frames are missing; the harness throws (→ skip) if they vanish mid-run. HD specifics: text regions come from the template's text layers (`RETRO_HD_TEXT` / `RETRO_HD_BOTTOM`: bigger type line ending before the expansion reference and never wider than the set-symbol clamp, P/T 14px higher, centred "Illus." + `number • set` bottom lines); the art window is cut at the template's art reference box and `card.artBounds` is set to the same box (`RETRO_HD_ART_BOUNDS`), so 3px of the 6px black art outline shows like Proxyshop; `rules.svg` is swapped for `frames/rules.png` (the template's land-textbox outline, hole-filled) so two-colour textboxes keep their pinline outline; the white frame is tinted to WotC's own retro white (`retro_hd._FRAME_TINT`, measured off SLD 7137/7138), so the pale-white workarounds (`retroNeedsTextOutline` / `PALE_RETRO_FRAMES`: outlines, softened shadows, black copyright) are skipped under `--retro-hd` and white text keeps packSeventh's plain shadow.
- No frame flag → style is `auto` (default for both the subcommand and a bare `#cardconjurer` modeline): the harness picks each card's frame from its resolved Scryfall `frame` (`SCRYFALL_FRAME_TO_STYLE`: 2015→modern, 2003→8th, 1997/1993→retro); frames with no CC equivalent (`future`, unknown) skip to `fallback.txt` for the raw scan. Resolved per-card in `runOneJob` (harness.js), only when `job.frame === 'auto'` — an explicit frame flag fully overrides it and renders every card in that frame, never skipping on frame. DFCs in auto render modern (real DFCs are 2015-frame); the 8th/retro/m15-8th DFC packs are reachable only via the explicit flags.
- Single-face generated tokens use Card Conjurer's native Original Tokens (Old Bordered) pack and its own loaded frame version, regardless of the deck frame. Keep tokens out of normal-card auto-framing, font-size overrides, and frame-specific text/bottom-info adjustments; the token version owns its fonts, geometry, text, and P/T layout. Unsupported double-faced token layouts retain their Scryfall token scan. The CLI supplies Scryfall's art-only crop for supported tokens, not the full token scan.

## Adventure / Prepare / planeswalker layouts

- `node/special_layouts.js` — dependency-free routing module (`resolveSpecialLayout`, `routePlaneswalkerDfcFace`, `validateSpecialLayout`), consumed by `harness.js` and directly unit-testable without Canvas. Adventure and Prepare (Scryfall `layout` 'adventure'/'prepare') always render through their dedicated modern-only packs (`packAdventure.js`/`packPrepare.js` via `autoFrameUnified('Adventure'|'Prepare')`) regardless of requested frame — `--8th`/`--m15-8th`/`--retro`/`--borderless` are all ignored for these layouts, since no non-modern furniture exists for the inset spell. Exception: `--retro-hd` renders them as one retro card with the Normal textbox split in half at the template's adventure divider (x 1095 template / 1008 card): `runOneJob` keeps the retro frame, `renderCard` flattens the card (`flattenAdventureForRetroHd`) into an ordinary retro card for the creature and carries the spell in `scry._adventure` (colour code + side: left for adventures, right for prepare cards), and `renderFace` remaps the Seventh frame images to `frames/adventure/<code>.png` (every land code → `l`; the creature's frame with a flat, unbevelled, pinline-free textbox, built by `retro_hd.py`'s `adventure-<code>` tasks) and overlays `frames/adventure/spell_<side>_<code>.png` (`adventure_spell_panel`: the spell's half in the spell's frame texture, an inset box of its textbox texture for its rules, a black divider between the halves and a black rule under the spell's type line). The creature's rules fill the other half; `advTitle` / `advMana` / `advType` (white on the panel) and `advRules` (inset box) carry the spell.
- Classic sagas (Scryfall layout `saga`, e.g. History of Benalia, Urza's Saga) render under `--retro-hd` only (plain `--retro` and other frames still fall back to the scan; transform sagas still skip): `resolveSpecialLayout` routes them on retro to `packClassicshiftedSaga.js` + CC's saga engine (`versionSaga.js`: chapter split incl. "I, II —", dividers), and `renderCard` lets them past `shouldSkip` only when `retroHd`. `retro_hd.py` builds the template's saga frames (`compose_variant(..., "Saga")` → `frames/saga/<w u b r g m l>.png`) plus its I–VI chapter badges and divider (`frames/saga/*.png`, positions in `extras.json`); the harness remaps the Classicshifted saga frames and divider to them and CC's chapter hexagon to a transparent pixel, `layoutRetroSaga` moves every region onto the template geometry (`RETRO_HD_SAGA`: chapter box left, tall art right, type line 587px lower, reminder box below it, packSeventh fonts, reminder text from the oracle text with Read ahead abridged like Proxyshop), `equalizeSagaChapters` gives all chapters one font size, and `redrawRetroSaga` (after the bleed margin) redraws the saga canvas, erases CC's divider above the first chapter and draws the template's numbered badges centred on each chapter.
- Retro planeswalkers (packPlaneswalkerSeventh, `--retro` and `--retro-hd`): `equalizePlaneswalkerAbilities` replaces CC's even split of the rules box (which auto-shrank each ability on its own, so sizes varied wildly on one card) with one shared font size -- the largest at which every ability, measured with `countWrappedLines`, plus `PW_ABILITY_PAD` lines each, fits the box -- sizes each ability box to its content, spreads slack evenly, and solves each `#planeswalker-shift-N` so the badge's NUMBER (not its image: minus/neutral shields have a tail) lines up with the ability's text centre (`PW_BADGE_NUMBER_CENTER`). `--retro-hd` fills the template's textbox (1697-2481, inset 12px).
- Planeswalkers are detected by `type_line` containing "Planeswalker", not by Scryfall `layout` (most single-face planeswalkers are `layout: 'normal'`). A single-face planeswalker renders native `packPlaneswalkerRegular.js` under auto/modern/`--8th`/`--m15-8th` (8th and M15-Eighth have no planeswalker furniture, so both normalize to modern), the Seventh-Edition `packPlaneswalkerSeventh.js` under `--retro`, and `packPlaneswalkerBorderless.js` under `--borderless`.
- A Transform or MDFC card with a planeswalker on either face always renders as two full-size faces (`forceSplit: true` in `resolveSpecialLayout`) — `--dfc-flip`/`job.dfc_split` is ignored for these, since no combined planeswalker template exists (`runOneJob` ORs `special.forceSplit` into its split decision). Each face routes independently via `routePlaneswalkerDfcFace`: a planeswalker face uses the native full-size planeswalker DFC packs (`packPlaneswalkerTransformFront/Back.js` + `packPlaneswalkerTransformIcons.js` for Transform, `packPlaneswalkerMDFC.js` for MDFC — the latter shared by both faces, disambiguated by `addFrameByName`'s `occurrence` param when both faces are the same color), while a non-planeswalker face keeps its ordinary DFC pack (`packM15TransformFront/Back.js`, `packModalRegular.js`). `--retro` on a Transform planeswalker DFC uses the Classicshifted planeswalker packs (`packClassicshiftedPlaneswalker.js` + `packClassicshiftedPlaneswalkerTransform.js`); MDFC has no Classicshifted planeswalker pack, so `--retro` on an MDFC planeswalker normalizes to modern like the other unsupported styles.
- `harness.js`'s `assertCompleteSpecialText()` throws if the native importer left any Adventure/Prepare text region or planeswalker loyalty/ability region empty; `runOneJob`'s existing catch-all turns that into a `status: 'skip'` response (no partial PNG ever written), so invalid or incomplete special-layout data falls back to the Scryfall scan like any other unrenderable card.
